# DCB 밸런싱·제어 글 구성

2026년 10월 19일 사용자 요청에 따른 작성 구조다. 게임 코드나 밸런스 값을 바꾸는 작업은 포함하지 않는다.

## 연결 구조

- 규칙·수치 분석의 분류는 `gameplay`, 이를 편집·관찰하는 에디터 도구 제작은 `tools`를 사용한다. 공통 태그는 `Balancing`, 프로젝트와 시리즈는 기존 `dcb`다. 별도 카테고리를 만들지 않는다.
- DCB 기능 `gameplay-balancing`의 `overviewSlug`는 `dcb-gameplay-balance-overview`, `articleSlugs`는 공개된 분석의 읽는 순서다.
- 첫 분석은 기존 `jige-carry-burden`이다. 기존 주소·날짜를 유지한다. 짐 출렁임의 분석 목록에서는 옮기되 두 본문의 관련 링크는 유지한다.
- 두 번째 분석은 도구 제작 경험 `player-balance-tuning-tool`이다. 도구와 구조 분류에서도 같은 밸런싱 기능 목록으로 연결한다.
- 세 번째 분석은 `locomotion-stamina-reinput`이다. 착용별 걸음 선택, 고갈 시 래치 해제·재선택 순서, 고정 스텝 소모와 입력 재현의 경계를 다룬다.
- 네 번째 분석은 `action-stamina-cost-and-recovery`다. 무기·착용별 비용, Animator 차감, 구르기 실패 복원과 회복 타이머를 추적하고 패리 경로의 차이를 구분한다. 배고픔·갈증의 현재 회복 시간·운반 한도·이동·체력·감소 규칙과 중립인 능력치 보정도 이 글에 포함한다.
- 다섯 번째 분석은 `movement-speed-modifier-stacking`이다. 실제 인벤토리 무게 곡선과 갈증·물·적재 수정자, 물 배율의 평활·해제와 스탯에서 실제 이동까지의 경계를 다룬다.
- 짐·다리의 스프링·스키닝·메시·충돌면 구조는 각 기능에 둔다. 속도·소모·회복·입력 제어와 만나는 조건을 밸런싱 글에서 연결한다.
- 새 글은 [작성 양식](templates/DCB-BALANCE-CASE.md)으로 초안을 만든다. 미작성 글의 빈 공개 주소나 초안 파일을 대량 생성하지 않는다.

## 각 글의 구성

1. 플레이어가 겪는 조건과 현재 규칙.
2. 입력/상태 → 데이터·카탈로그 → 계산 → 최종 이동·자원·행동의 실제 적용 경로.
3. 코드 기본값·저장값·런타임 값과 활성 여부. 출처의 확인일·대표 커밋 AuthorDate.
4. 조정한 값·규칙과 이유. 변경하지 않은 경우 현재 구조와 변경 후보를 구분.
5. 변경 전후 비교 조건, 측정 단위, 실행 결과 또는 미실행 계산 예상.
6. 부작용·재현 조건·미검증 항목, 본인 기여·AI 보조 범위.

비교 기록에는 코드 ref, 적용 카탈로그, 맵·동선·경사, 시작 자원·적재량, 입력 시점·지속 시간, 프레임/물리 시간 조건을 남긴다. 여러 요소를 바꿨다면 변경별 효과를 나누어 설명할 수 있는지 적는다. 가속 목표와 실제 이동, 표면에 실린 이동, 루트 모션과 충돌 때문에 제한된 이동을 구분한다.

최초 구조 마련에서는 DCB 소스 재조사·수치 변경·Unity 실행·균형 비교를 수행하지 않았다. 이후 각 글은 해당 작업을 실제로 수행한 범위에서만 결과를 채운다. 하네스·검사 코드가 있다는 사실만으로 체감이나 플레이 검증을 통과했다고 쓰지 않는다.

## 게시와 관리

초안 작성 → 문구·근거 검토 → 승인된 글 공개 → 기능의 `articleSlugs`에 추가 → `npm run verify` → Home·긴 글·모바일 검색 확인 → main push → Actions와 공개 페이지 확인 순서다. 글 제목·주소는 실제 작성 때 정한다. 이 계획의 순서 번호는 시리즈의 `order`와 별개다.
