# 프로젝트 기술 학습 글 목록

2026년 10월 17일 기준의 집필 목록이다. DCB의 코드 폴더, 시스템 문서 색인, 패키지 목록과 현재 블로그를 대조했다. 장비·몬스터 글은 실제 호출 경로와 수정 이력까지 확인했다. 나머지 항목의 연결 근거는 코드·문서의 존재이며, 개별 글을 쓸 때 실제 호출·자산 연결과 실행 상태를 다시 확인한다.

목표는 **이 블로그의 설명과 예제만으로 개념을 익히고, DCB에서 그 개념이 어떻게 사용되는지 따라갈 수 있게 만드는 것**이다. 기존 포트폴리오 글은 시스템 개요와 사례로 유지하고, 기초·원리·실습 글을 연결한다. 아래는 장기 집필 후보이며 지원일까지 전부 작성하는 일정이 아니다.

현재 목록은 **21개 영역, 189개 글 후보**다. DCB에 연결된 기초·구현·개발 운영 155개, 별도 imjaess 하네스 12개, 블로그 기술 8개, 후속 기획 4개, LearnOpenGL 10개로 구성한다. 공개 글로 이미 개요를 다룬 주제도 포함하므로 189개 모두가 새 글이라는 뜻은 아니다.

사용자 요청에 따라 C# 문법 입문 글은 제외했다. 변수·조건문·반복문·메서드를 읽는 수준은 전제하고, 첫 묶음은 자료구조의 원리·선택·구현·실습으로 시작한다. 언어 기능은 프로젝트 주제를 설명하는 데 필요한 곳에서 다룬다.

## 글마다 갖출 학습 구성

1. **시작 조건:** 필요한 선행 글, 사용할 Unity·언어·패키지 버전, 준비할 빈 예제.
2. **개념 설명:** 용어를 처음 정의하고 목적·동작 원리·실패 조건을 설명한다. 외부 링크를 읽어야 본문을 이해할 수 있는 구성을 피한다.
3. **작은 예제:** 비공개 소스를 복사하지 않은 최소 예제를 제공한다. 입력, 처리 순서, 예상 결과와 중요한 코드 줄을 해설한다.
4. **프로젝트 적용:** DCB에서 사용한 데이터·호출·자산의 관계, 선택한 이유와 비용, 실제 문제 해결 사례를 연결한다.
5. **실습:** 독자가 바꿀 값이나 재현할 오류, 확인할 출력·화면, 실패했을 때 점검할 곳을 적는다.
6. **확인 질문:** 설명·계산·수정 과제와 풀이를 제공한다. API 이름을 외우는 것에서 끝내지 않는다.
7. **확인 범위:** 예제 실행, 현재 소스 확인, 과거 검사, 최신 게임 재생과 측정 결과를 구분한다. AI 보조와 재사용 자산도 필요한 곳에서 설명한다.

아직 준비되지 않은 영상·수치·풀이 결과는 만들지 않는다. 실제 글은 `content/articles/<topic>/`에 초안으로 작성한다. 이 목록만으로 새 주소나 빈 초안 파일을 대량 생성하지 않는다.

## U 별도 프로젝트 LearnOpenGL

선행: C++ 코드 읽기, B01·B04. 연결 근거: [imjae/LearnOpenGL](https://github.com/imjae/LearnOpenGL)의 현재 main `bc9d85f`와 로컬 동일 커밋. `Chapter01/Main.cpp`, GLSL 두 파일, Shader 도우미와 Visual Studio 설정을 확인했다. 최신 빌드·GLSL 컴파일·GPU 실행은 하지 않았다. [구현 연결 글](../content/articles/graphics/opengl-vertex-texture-pipeline.md)을 검토해 6e5d39f에서 게시했다.

## 먼저 집필할 묶음

지원 준비에서는 기존 대표 글의 실행 근거와 제출물을 우선한다. 장기 학습 글의 첫 묶음은 다음 순서로 진행한다.

1. A01: 컬렉션 선택·내부 동작·비용·실습 네 개부터 학습. 문법 입문은 제외한다.
2. A02·A04~A07: 동적 배열·해시·큐·스택·트리로 확장. 연결 리스트·힙·그래프는 해당 필요에 따라 이어 읽는다.
3. B01~B04, B07~B08: 방향·회전·좌표·범위·시간.
4. C01~C04, C05~C07: 실행 순서·조합·상태·수명·소유권.
5. A07과 I01~I04: 파츠 트리와 조립 알고리즘. 현재 장비 글을 읽을 기반 확보.
6. I06~I09와 D06: 프리뷰가 사라진 사례부터 풀·복사·저장까지 연결.
7. H06~H10, G05~G10: 몬스터와 IK의 실제 사례를 학습 글로 확장.
8. U01~U08: OpenGL의 현재 학습 코드에서 버퍼·셰이더·텍스처 연결을 설명. U09의 좌표 변환·깊이는 새 실습으로 진행.
9. K01~K06과 L01~L06: Unity 렌더링 기초에서 물 캐시의 버퍼·스레드·업로드로 진행.
10. 남은 환경·사운드·도구·웹 글을 해당 기초와 연결한다.

각 묶음의 첫 글을 쓴 뒤 예제를 실제로 따라가며 빠진 선행 개념을 보완한다. 목록 순서만 채우기 위해 설명이 없는 코드나 확인되지 않은 결과를 넣지 않는다.

## 추가 연결을 확인할 기술

`Packages/manifest.json`에 있다는 이유만으로 실사용 사례로 넣지 않는다. Cinemachine·Animation Rigging·Unity Timeline·Multiplayer Center·URP·AI Assistant 등의 실제 호출·씬·자산 연결은 별도 확인 대상이다. 프로젝트의 자체 `AnimationEffectTimeline`을 Unity Timeline 패키지 사용 사례와 혼동하지 않는다.

현재 코드에서는 Input System, Addressables, DOTween, Newtonsoft.Json, NativeArray·Job·Burst, Compute Shader·AsyncGPUReadback, UnityWebRequest의 참조를 확인했다. 이 목록도 어느 씬에서 어떤 옵션으로 동작하는지와 성능 효과까지 확정한 목록은 아니다. 외부·재사용 패키지의 기능과 직접 구현을 구분한다.

DCB 외의 다른 게임 프로젝트는 이번 전체 목록 감사 범위에 포함하지 않았다. imjaess·블로그와 LearnOpenGL을 별도 묶음으로 연결했다. 이후 다른 프로젝트를 포함할 때는 그 소스와 작업 기록을 확인해 확장한다.

## 근거와 참고 문서 관리

- DCB의 시스템 문서 색인, 아키텍처, Scripts·Shaders·Editor·Tests 폴더와 패키지 목록을 출발점으로 사용한다. 매 글의 실제 입력·호출·프리팹·데이터를 집필 전에 확인한다.
- 기초 정의는 [Microsoft C# 가이드](https://learn.microsoft.com/ko-kr/dotnet/csharp/)와 [Unity 6.3 매뉴얼](https://docs.unity3d.com/6000.3/Documentation/Manual/UnityManual.html)을 대조한다. 사용 중인 버전과 다른 API 예제를 그대로 적용하지 않는다.
- 개발 운영과 별도 도구의 기초는 [Git 문서](https://git-scm.com/doc)와 [SQLite 문서](https://www.sqlite.org/docs.html)를 참고한다. 공식 문서 링크는 본문 설명을 보충하는 용도로 제공한다.
- 공개 설명에는 전체 비공개 소스·원본 로그·개인 경로·데이터·인증 정보를 복사하지 않는다. 예제와 도식은 독립적으로 작성하고, 캡처·영상은 승인된 자료를 사용한다.
