# DCB 촬영·블로그 첨부 준비

촬영 시작 예정일은 **2026년 10월 19일**이다. 이 문서는 촬영할 장면과 수집할 정보를 정리한 계획이며, 아래 항목은 모두 촬영 전 상태다. 게임 조작·검증은 DCB에서 진행하고, 파일 선별·캡션·본문 첨부는 이 블로그에서 진행한다.

## 첫날 순서

1. 일반 시작으로 게임에 진입하고 사용할 씬·캐릭터·저장 상태를 확인한다. 진입에 실패하면 그 원인을 먼저 해결한다.
2. 지게 운반 → 몬스터 전투 → FSM 도구 → 장비 조합 → IK 순으로 핵심 장면을 확보한다.
3. 물 → 불을 같은 게임 카메라에서 촬영한다. VFX 타임라인과 성능 기록은 추가 묶음으로 둔다.
4. 후보를 함께 검토하고, 공개할 구간과 설명을 정한 뒤 블로그 첨부본을 만든다.

첫날에는 각 사례의 정상 속도 원본 한 개와 필요한 근접 장면부터 확보한다. 세부 검증이 막히면 촬영 기록에 이유를 남기고 다음 사례로 넘어간다. 모든 검증을 한 편의 소개 영상 안에 넣을 필요는 없다.

## 사례별 촬영 지시

### CAP-01 지게 운반

같은 짧은 길을 맨몸과 지게 상태로 이동한다. 걷기·달리기, 스태미너 소모·회복, 내려놓기 후 이동을 보여 준다. 여유가 있으면 고갈 후 버튼을 계속 누른 상태와 다시 누른 상태를 나누어 찍는다.

현재 글에서 확인한 적재 속도·소모·회복 곡선은 모두 배율 1이다. 빈 지게와 적재한 지게를 촬영하더라도 적재량에 따른 추가 감속을 성과로 설명하지 않는다. 촬영 전 설정이 바뀌었다면 실제 값과 변경 커밋을 먼저 기록한다.

첨부 위치: 글 도입부 다음에 기본 운반 시연을 배치한다. 고갈·재입력 장면은 해당 설명 옆에 따로 붙인다.

### CAP-02 몬스터 전투

몬스터 수·종류와 시작 위치를 기록한다. 잠시 정지한 뒤 플레이어만 방향을 바꾸고, 옆으로 이동하고, 공격 중인 적을 중단시키거나 처치한 뒤 전투를 이어 간다. 자리 재배치와 공격 기회가 어떻게 이어지는지 충분히 남긴다.

주요 확인 항목은 상태 전환 중 이동 공백, 포위 대열의 회전, 공격 중단·사망 뒤 후속 공격의 진행이다. 화면에 보이는 공격자 수만으로 토큰·클레임 반환이나 모든 상황의 동시 공격 상한을 입증하지 않는다. 필요하면 같은 실행의 관련 상태를 별도 도구 기록과 연결한다.

첨부 위치: 도입부에는 일반 전투를, 기준축·공격 권한 설명 옆에는 해당 동작의 짧은 구간을 배치한다.

### CAP-03 FSM·DSL 도구와 실제 패턴

공개할 수 있는 패턴 정의의 작은 부분과 뷰어의 대응 상태·전이를 보여 준 뒤 같은 패턴을 게임에서 재생한다. 화면에 표시할 상태 이름은 실제 definition과 맞춘다. 편집과 재생 사이에 컴파일·재시작이 있었다면 편집본의 전환도 구분한다.

현재 일반 스폰은 뷰어 preset을 자동으로 읽지 않는다. 선택 개체 시험 적용과 일반 스폰을 구분하고, 코드 변경 없이 모든 패턴이 즉시 반영되는 것처럼 설명하지 않는다. 전환 전 Behavior 영상이 없으면 현재 작업 흐름을 보여 준다.

첨부 위치: 코드 원본·뷰어·튜닝 도구의 역할을 설명하는 절에 도구 화면과 실제 전투를 연결한다.

### CAP-04 장비 조합과 복원

이름을 기록한 동일 파츠로 2D 조립, 3D 프리뷰 회전, 장착, 드랍·회수를 찍는다. 파츠를 교체하거나 제거했을 때 이전 표현이 남는지도 확인한다. 프리뷰의 효과·크기·피벗 문제를 설명할 수 있도록 같은 장비의 가까운 장면을 남긴다.

저장·재실행은 별도의 긴 원본으로 남긴다. 재실행 전후 파츠 구성과 표시 스탯을 대조한다. 로딩을 편집으로 덜어 낸 구간은 캡션에 표시한다. 조립부터 회수까지만 촬영했다면 저장 왕복까지 검증한 것으로 쓰지 않는다.

첨부 위치: 조립 흐름 뒤에 기본 시연을 넣고, 복원 확인을 완료한 경우 저장 절에 추가한다.

### CAP-13 장비 조합 UI 이펙트

CAP-04에서 같은 조합을 유지한 채 연출을 보충 촬영한다. 길쭉한 파츠와 짧은 파츠를 각각 붙여 접촉 시점·연기 방향을 남긴다. 직선 무기와 낫의 조합 완료를 정상 속도로 촬영하고, 분사 입자의 무기 도착·코일 전환·끝부분 소멸과 결과 1.5배 확대를 근접 구간으로 확인한다. UI 클릭과 패드 조작을 가리는지, 연출 중 닫았다 다시 열었을 때 입자가 남는지도 확인한다.

현재 저장값은 코일 200개·0.5초 분출·개별 비행 0.65~0.95초다. 게임 시간 배율과 해상도·화면 비율을 기록한다. UI 변환을 추적하는 2D 축 연출이며 실제 3D 메시 표면 충돌을 보여주는 영상으로 설명하지 않는다. 현재 다중 파츠의 지속 연기 밀림 상태는 하나이므로 생성 위치와 바람 반응을 구분해 관찰한다. 과거 시각 검사 도구의 소스만으로 이번 촬영이 통과한 것으로 처리하지 않는다.

첨부 위치: 새 글 도입부에는 전체 연출을, 비행·코일 속도 연결과 결과 확대 설명 옆에는 같은 실행의 근접 구간을 둔다. 아직 초안이며 실제 영상 ID를 받기 전에는 플레이어를 붙이지 않는다.

### CAP-05·06 IK 트레버설

일반 게임 속도로 진입부터 보행 복귀까지 한 번에 찍는다. 같은 구간을 손발과 관절이 보이는 각도에서도 반복한다. 좌우 진입·반대 방향 이동을 포함하고, 손목·발목의 꺾임, 팔꿈치·무릎 방향과 해제 순간을 확인한다.

턱 높이와 Avatar를 기록하며 명목상 애니메이션 이름만으로 실제 높이를 단정하지 않는다. 높은 StepUp의 발 튐이나 접촉 문제가 남으면 검토 원본에 남기고 글의 한계 설명도 유지한다. 짧은 성공 장면만으로 모든 높이·방향의 품질을 통과 처리하지 않는다.

첨부 위치: 도입부에는 정상 속도 전체 동작, 문제·수정 설명 옆에는 같은 동작의 접촉 근접 장면을 둔다. 슬로모션은 보충으로만 사용하고 배속을 표시한다.

### CAP-07·12 물 캐시

일반 게임 카메라에서 수면과 지형 접점을 촬영한다. 현재 캐시가 반복 전환을 두 번 이상 지나도록 원본 길이를 잡는다. 카메라를 멀리 또는 화면 밖으로 보냈다가 복귀하는 장면도 남긴다. 정지·탐색·재개는 실제 제공되는 저작 도구에서 조작할 수 있는 경우 별도의 도구 화면으로 찍는다.

현재 주요 급류 프리팹은 Forest01Final 캐시를 사용하며 비대기 옵션은 꺼져 있다. 촬영 때의 캐시·loop·대기 정책·거리 조건을 기록한다. 영상 준비를 위해 이를 임의로 바꾸지 않는다. 비교하려고 바꾼 경우에는 두 설정과 촬영 구간을 각각 남긴다.

성능을 추가로 설명하려면 같은 캐시·카메라·시각·품질에서 워밍업과 표본 수를 맞추고 CPU 읽기·대기·업로드와 GPU를 따로 기록한다. 일반 재생 영상과 Profiler 화면만으로 현재 FPS 개선율을 만들지 않는다. 기존 실패 검사 2건의 상태는 별도 결과가 생기기 전까지 유지한다.

첨부 위치: 도입부에는 실제 재생·접점을, 반복·대기 설명 옆에는 해당 구간을 배치한다. 성능 결과는 조건과 원본 측정 자료를 확보한 경우에만 해당 표 아래 추가한다.

### CAP-08·09 불과 VFX

하나의 불을 가까이에서 본 뒤 멀리 이동하고 다시 접근한다. 품질 경계 근처에서 잠시 머물며 표현이 반복해서 바뀌거나 시간이 초기화되는지 확인한다. 실제 품질 단계 이름을 보여 주려면 해당 상태를 확인할 수 있는 도구 기록도 함께 남긴다.

타임라인은 발생 프레임·부착점 설정과 실제 캐릭터 동작을 대응시킨다. 효과의 시작뿐 아니라 종료·반환 뒤 잔존 여부도 찍는다. 저장된 설정·자동 검사·게임 재생·Player 재생의 확인 범위를 각각 기록한다.

첨부 위치: 레이어 구성 뒤에는 일반 재생, 품질 단계 옆에는 거리 변화, 타임라인 절에는 저작 화면과 실제 발생 장면을 배치한다.

## 파일과 촬영 기록 넘기기

원본은 저장소 루트의 **`media-inbox/`**에 둔다. 이 폴더의 영상·프로젝트 파일은 Git에서 제외한다. 영상은 사용자 선택에 따라 YouTube 등에 올려 본문에 삽입한다. 별도로 사용할 실제 대표 이미지와 보충 이미지만 `public/media/<slug>/`에 넣는다. DCB의 원본 씬·에셋·저장 데이터를 이 블로그로 복사할 필요는 없다.

파일명은 다음처럼 사용한다. `take`는 재촬영 순번, `raw`는 원본, `cut`은 첨부 후보를 뜻한다.

```text
2026-10-19_monster-combat_turn_take01_raw.mp4
2026-10-19_monster-combat_turn_take01_cut.mp4
2026-10-19_monster-combat_turn_take01_poster.webp
```

[촬영 기록 양식](templates/DCB-TAKE.md)을 take마다 복사하고, 원본 파일 위치와 사용할 타임코드만 먼저 적어도 된다. 나머지 조건은 실제 값으로 채운다. 공개 후보의 대표 이미지는 해당 영상의 실제 프레임에서 고른다.

기록 상태는 `planned → recorded → reviewed → approved → attached → live-checked`로 구분한다. `approved`는 사용자가 공개할 구간을 정한 상태, `attached`는 로컬 본문 연결, `live-checked`는 배포 후 공개 재생까지 확인한 상태다. 영상 파일을 받았다는 이유만으로 실행 검증 항목 전체를 완료로 바꾸지 않는다.

## 블로그 첨부 방식

사용자가 **YouTube 등에 업로드한 뒤 본문에 삽입**하는 방식을 선택했다. 원본과 편집본은 로컬에 보존하고 영상 파일을 이 Pages 저장소에 배포하지 않는다. 각 글에는 핵심 장면의 영상 또는 전체 영상의 해당 구간을 붙인다.

프로젝트 소개의 짧은 게임 영상은 `/portfolio/dcb/`에서 **수정 모드 → DCB 게임 영상**으로 주소를 등록한다. GitHub에서 설정을 저장·배포하면 소개 상단에 **게임 영상 보기**가 표시된다. 이 버튼은 외부 영상으로 이동하는 링크이며 글의 구간별 삽입과 별도로 관리한다. 아직 촬영 전이므로 주소는 비어 있고 공개 버튼도 숨겨 둔다.

1. 사용할 원본 구간과 편집본을 정한다. 기능별 20~50초 영상과 약 3분 전체 소개 영상이 기본 후보이며 실제 내용에 맞춰 길이를 조정한다.
2. 사용자 채널에 업로드하고 제목·설명·필요한 자막을 넣는다. 공개 또는 미등록 중 실제 공개 범위를 정하고 삽입을 허용한다. 미등록 영상도 링크를 가진 사람이 볼 수 있다. [YouTube 공개 범위 안내](https://support.google.com/youtube/answer/157177)
3. HD 처리가 끝난 뒤 YouTube 주소·쓸 구간·촬영 기록을 이 블로그 작업에 전달한다. 같은 전체 영상을 여러 글에서 사용하면 글별 시작·종료 타임코드를 적는다.
4. [YouTube HTML 양식](templates/youtube-figure.html)의 `VIDEO_ID`·제목·캡션을 실제 값으로 채워 해당 설명 옆에 넣는다.
5. 로그아웃한 공개 주소와 모바일에서 재생·탐색·전체 화면·원본 링크를 확인한다. 실제 영상의 검증과 로컬 레이아웃 검증은 따로 기록한다.

양식은 `youtube-nocookie.com` 삽입 주소와 `loading="lazy"`, 모바일 인라인 재생, 원본 링크를 사용한다. 자동 재생·자동 반복은 넣지 않는다. 화면 폭에 맞춘 16:9를 기본으로 하며 모바일에서도 최소 높이 200px을 확보한다. [YouTube 삽입 안내](https://support.google.com/youtube/answer/171780), [플레이어 크기와 매개변수](https://developers.google.com/youtube/player_parameters)

전체 영상에서 15~45초를 보여 줄 때 삽입 주소 뒤에 `&amp;start=15&amp;end=45`를 추가할 수 있다. 종료 값도 전체 영상 시작 기준의 초다. 정밀하게 잘라야 하는 장면은 별도 편집본을 올린다. `rel=0`은 관련 영상을 같은 채널로 제한하며, 관련 영상 자체를 제거하지 않는다. 이 동작은 위 플레이어 문서를 따른다.

빈 플레이어나 임시 썸네일은 공개 글에 넣지 않는다. 업로드 API·API key·YouTube 로그인 정보를 사이트에 추가하지 않는다. 실제 영상 주소를 받기 전까지 공개 글의 영상 영역은 만들지 않는다.

설명은 다음 정보를 담는다.

```text
[기능과 장면]. [촬영일], [Editor/Player], [해상도·녹화 fps], [재생 배속].
[이 구간에서 확인한 동작]. [별도로 남은 검증].
```

영상의 녹화 날짜와 글의 원래 작업 날짜는 구분한다. 기존 `date`·slug는 유지하고 영상 첨부일은 `updated`와 캡션에 반영한다. 재사용 모델·애니메이션·텍스처와 AI 보조 범위도 기존 설명을 유지한다.

## 약 3분 소개 영상의 편집 후보

| 구간 | 내용 |
| --- | --- |
| 0:00~0:15 | 지게 운반으로 게임의 기본 조작과 분위기 소개 |
| 0:15~0:45 | 몬스터 그룹 전투 |
| 0:45~1:00 | FSM·DSL 정의·뷰어와 전투 연결 |
| 1:00~1:30 | 장비 파츠 조합과 실제 장착 |
| 1:30~2:15 | StepUp·Climb·SideStep |
| 2:15~2:35 | 물 재생·지형 접점 |
| 2:35~2:55 | 불과 타임라인 효과 |
| 2:55~3:00 | 담당 범위·상세 글 안내 |

이 순서는 촬영 결과를 보고 조정할 편집안이다. 블로그의 각 글에는 전체 소개 영상만 반복해서 넣기보다 해당 기능의 짧은 구간을 먼저 연결한다. 실제 영상이 준비되면 포트폴리오의 소개 영역에도 배치한다.
