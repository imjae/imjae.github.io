# 글쓰기와 정리 가이드

글은 Markdown 파일 하나로 작성합니다. 폴더는 넓은 기술 영역, 태그는 세부 기술, 시리즈는 읽는 순서, 프로젝트는 소속 작업을 뜻합니다.

주제는 게임플레이(`gameplay`), 그래픽스(`graphics`), 도구와 구조(`tools`), AI 협업(`ai`), 학습 메모(`notes`), 수학(`math`)을 사용합니다. 수학의 수·함수·벡터·행렬·회전 설명은 `math`에 모으고, 엔진이나 렌더링 API를 중심으로 다루는 글은 해당 기술 주제에 둡니다.

문구를 작성하거나 수정하기 전에 [블로그 문구 작성 지침](EDITORIAL.md)을 읽습니다. 이 문서는 파일 구성과 게시 절차를 다룹니다.

## 웹에서 추가·수정·삭제

블로그 상단의 **수정 모드** 또는 https://imjae.github.io/editor/ 를 엽니다. 이 화면은 GitHub의 편집 기능으로 연결합니다. 실제 저장은 GitHub 로그인 후 저장소 쓰기 권한이 있는 계정으로 진행합니다.

- **새 글:** 제목·요약·주소·분류를 입력하고 **GitHub에서 새 글 작성**을 누릅니다. 기본 정보와 본문 틀이 채워진 화면에서 이어서 작성합니다. 새 글은 `draft: true`로 시작합니다.
- **수정:** 공개 글 목록에서 해당 글의 **수정**을 누릅니다. 본문과 메타데이터를 편집하고 **Commit changes**로 저장합니다. 기존 `slug`는 유지합니다.
- **삭제:** 해당 글의 **삭제 검토**를 누릅니다. GitHub에서 파일과 변경 내용을 확인하고 삭제를 커밋하면 반영됩니다. 원본 Jekyll 보관 파일은 별도로 유지합니다.
- **초안:** **초안·전체 파일**에서 GitHub의 파일 목록을 엽니다. `draft: true`인 글은 블로그의 수정 모드 목록에도 표시하지 않습니다.

공개하려면 `draft: false`로 바꿔 `main`에 저장합니다. 검증과 배포가 끝나면 블로그에 반영됩니다. **배포 확인**에서 성공 여부를 확인할 수 있습니다. 블로그의 본문에는 Markdown을 사용합니다. GitHub의 Preview는 일부 수식·다이어그램 표시가 블로그와 다를 수 있습니다.

수정 모드 자체는 누구나 볼 수 있습니다. GitHub가 로그인과 저장 권한을 확인하며, 블로그는 로그인 정보나 토큰을 받지 않습니다. 기능별 동작은 [GitHub 파일 관리 안내](https://docs.github.com/en/repositories/working-with-files/managing-files)를 참고합니다.

## 로컬에서 작성

### 1 새 글 만들기

```sh
npm run new -- --title "손 지지가 끊기는 Climb 전환" --slug climb-hand-contact --topic gameplay --kind devlog --project dcb --series dcb
```

주소는 영문 소문자·숫자·하이픈으로 정하고 공개 후 유지합니다. 같은 주소가 있으면 덮어쓰지 않습니다. `kind`는 `case-study` 구조 노트, `devlog` 개발 기록, `note` 기술 노트, `reading` 읽기 노트입니다.

### 2 메타데이터 채우기

```yaml
---
title: "손 지지가 끊기는 Climb 전환"
description: "같은 지형과 입력에서 접촉 해제 시점을 비교한 기록입니다."
slug: "climb-hand-contact"
date: "2026-10-17"
topic: "gameplay"
kind: "devlog"
tags: ["Unity", "IK", "Traversal"]
project: "dcb"
series: "dcb"
order: 7
draft: true
---
```

날짜는 한국 기준 `YYYY-MM-DD`입니다. 글 생성 명령이 오늘 날짜를 채웁니다. 큰 수정에는 `updated`를 추가합니다. DCB 시리즈 글은 `order` 순으로 연결되고, 태그는 기존 표기를 재사용합니다.

### 3 본문 구성

대표 사례는 **문제 → 구조와 구현 → 선택과 비용 → 검증 범위 → 남은 일**로 작성합니다. 개발 기록은 목표·관찰·결과·다음 작업으로 짧게 남겨도 됩니다. 제목은 위 메타데이터가 표시하므로 본문은 `##`부터 시작합니다. `##`, `###`는 우측 목차에 자동으로 나타납니다.

코드 블록에 `csharp`, `hlsl`, `json` 등의 언어를 적으면 강조와 복사 버튼이 붙습니다. 흐름도는 `mermaid` 코드 블록으로, 수식은 `$...$` 또는 `$$...$$`로 작성합니다. 표는 일반 Markdown 표를 사용합니다.

이미지는 `public/media/글주소/`에 넣고 `/media/글주소/이미지.webp`처럼 참조합니다. 큰 영상은 사용자 소유의 공개 영상 링크를 사용합니다. 실제 장면이 준비되지 않았으면 영상 버튼이나 가짜 썸네일을 만들지 않습니다.

### 4 로컬에서 보기

`npm run dev`의 주소를 엽니다. 이때 초안에는 로컬 표시가 붙습니다. 공개 상태를 확인하려면 `npm run verify` 후 `npm run preview`를 사용합니다. 초안은 정적 페이지·목록·본문 검색·RSS·sitemap에 포함되지 않습니다.

제목과 본문, 태그는 글 모아보기에서 함께 검색합니다. 검색어와 필터는 URL에 반영되어 같은 결과를 링크로 공유할 수 있습니다. 검색창 단축키는 `/`입니다.

### 5 공개하기

설명과 본문을 완성한 뒤 `draft: false`로 바꿉니다. `npm run verify`를 통과하고 커밋한 뒤 `main`에 push합니다. Actions의 배포가 성공하면 같은 주소에 반영됩니다. 대표 시스템의 소개는 `src/data/site.ts`와 `/portfolio/dcb/`에서 관리하고 실제 설명은 글로 연결합니다.

공개 전에는 원본 자산과 본인 기여, AI 보조 범위, 실제 측정 조건을 확인합니다. private 게임 저장소의 전체 코드·로컬 경로·로그·세이브는 블로그에 복사하지 않습니다.
