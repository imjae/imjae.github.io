# 글쓰기와 정리 가이드

글은 Markdown 파일 하나로 작성합니다. 폴더는 넓은 기술 영역, 태그는 세부 기술, 시리즈는 읽는 순서, 프로젝트는 소속 작업을 뜻합니다.

주제는 Gameplay(`gameplay`), Graphics(`graphics`), Tools & Systems(`tools`), AI Collaboration(`ai`), Notes(`notes`), Mathematics(`math`), Reading(`reading`)을 사용합니다. 수학의 수·함수·벡터·행렬·회전 설명은 `math`에 모으고, 엔진이나 렌더링 API를 중심으로 다루는 글은 해당 기술 주제에 둡니다. 책 목록과 독후감은 `reading`에 모읍니다.

문구를 작성하거나 수정하기 전에 [블로그 문구 작성 지침](EDITORIAL.md)을 읽습니다. 이 문서는 파일 구성과 게시 절차를 다룹니다.

## 웹에서 추가·수정·삭제

글 본문에서 상단의 **Edit ↗**를 누르면 해당 Markdown 파일의 GitHub 편집 화면이 새 탭으로 열립니다. 목록에서 글을 다시 찾을 필요 없이 본문과 메타데이터를 수정할 수 있습니다. GitHub 로그인과 저장소 쓰기 권한이 필요하며 **Commit changes**로 저장합니다.

Home·목록의 **Edit** 또는 https://imjae.github.io/editor/ 는 글 목록·고정·새 글 작성을 관리하는 화면을 엽니다. 실제 저장은 GitHub의 인증된 편집 기능에서 진행합니다.

- **새 글:** 제목·요약·주소·분류를 입력하고 **GitHub에서 새 글 작성**을 누릅니다. 기본 정보와 본문 틀이 채워진 화면에서 이어서 작성합니다. 새 글은 `draft: true`로 시작합니다.
- **수정:** 글 본문 상단의 **Edit ↗** 또는 관리 목록에서 해당 글의 **수정**을 누릅니다. 본문과 메타데이터를 편집하고 **Commit changes**로 저장합니다. 기존 `slug`는 유지합니다.
- **삭제:** 해당 글의 **삭제 검토**를 누릅니다. GitHub에서 파일과 변경 내용을 확인하고 삭제를 커밋하면 반영됩니다. 원본 Jekyll 보관 파일은 별도로 유지합니다.
- **초안:** **초안·전체 파일**에서 GitHub의 파일 목록을 엽니다. `draft: true`인 글은 블로그의 수정 모드 목록에도 표시하지 않습니다.
- **홈 고정 글:** 공개 글 목록의 **고정·고정 해제**로 선택하고, 위의 **홈 고정 글**에서 ↑·↓로 순서를 바꿉니다. **GitHub에서 고정 설정 저장**을 누른 뒤 GitHub에서 **Commit changes**로 확정합니다. 배포가 끝나면 Home과 수정 모드에 같은 순서가 반영됩니다. 저장 전 변경은 현재 탭의 세션에 보관하며, **변경 취소**는 현재 게시된 설정으로 되돌립니다.
- **DCB 게임 영상:** 프로젝트 소개에서 **Edit**를 누르면 **DCB 게임 영상**으로 이동합니다. YouTube 등의 HTTPS 영상 주소를 입력하고 **GitHub에서 영상 설정 저장** → **Commit changes**로 확정합니다. 배포 후 소개 상단에 **게임 영상 보기** 버튼이 표시됩니다. 주소를 비우고 같은 방식으로 저장하면 버튼을 숨깁니다. 영상은 새 탭에서 열며, 주소가 없을 때는 공개 화면에 빈 버튼이나 플레이어를 만들지 않습니다.

공개하려면 `draft: false`로 바꿔 `main`에 저장합니다. 검증과 배포가 끝나면 블로그에 반영됩니다. **배포 확인**에서 성공 여부를 확인할 수 있습니다. 블로그의 본문에는 Markdown을 사용합니다. GitHub의 Preview는 일부 수식·다이어그램 표시가 블로그와 다를 수 있습니다.

수정 모드 자체는 누구나 볼 수 있습니다. GitHub가 로그인과 저장 권한을 확인하며, 블로그는 로그인 정보나 토큰을 받지 않습니다. 기능별 동작은 [GitHub 파일 관리 안내](https://docs.github.com/en/repositories/working-with-files/managing-files)를 참고합니다.

DCB 영상 설정은 `content/project-videos/`의 새 JSON 파일로 저장합니다. 빌드는 `createdAt`이 가장 최근인 설정의 `videoUrl`을 사용하며, 빈 문자열은 영상 버튼을 숨기는 설정입니다. 이전 파일을 남겨도 최신 제거 설정이 우선합니다. 이 기능은 영상 주소만 연결하며 파일 업로드·영상 공개 범위를 변경하지 않습니다.

## 독서 기록

`/topics/reading/`은 책 제목·저자·완독일과 짧은 감상을 보여주는 Bookshelf입니다. 완독일이 비어 있으면 글 작성일을 **기록** 날짜로 표시합니다. 짧은 감상이 없는 기존 글은 설명을 **기록 요약**으로 표시합니다. 제목이나 **독서 메모 읽기**를 누르면 같은 글의 본문으로 이동합니다.

Reading의 **독서 기록 추가** 또는 Edit에서 Topic을 **Reading**으로 선택합니다. 글 제목·요약·주소·작성 날짜와 함께 책 제목(필수), 저자·완독일·짧은 감상(선택)을 입력합니다. 글 종류는 `reading`으로 지정되고, 짧은 감상은 최대 280자까지 목록과 글 상단에 표시됩니다. 저장은 기존과 같이 GitHub에서 합니다. 새 기록은 초안이며 `draft: false`로 공개한 뒤 배포해야 목록·검색에 나타납니다. 본문에는 긴 독후감이나 추가 메모를 이어 쓸 수 있습니다.

로컬 생성 예시:

```sh
npm run new -- --title "책 제목 독서 메모" --slug book-reading-note --topic reading --book-title "책 제목" --book-author "저자" --book-note "직접 작성한 짧은 감상"
```

완독일을 알고 있으면 `--book-finished "2026-10-19"`처럼 추가합니다. 메타데이터는 다음 형식이며 선택 항목은 생략할 수 있습니다.

```yaml
topic: reading
kind: reading
book:
  title: "책 제목"
  author: "저자"
  finished: "2026-10-19"
  note: "직접 작성한 짧은 감상"
draft: true
```

새 파일은 `content/articles/reading/`에 둡니다. 기존 「시지프 신화」 글은 이 폴더로 옮겼으며, 원래 날짜·slug·본문과 `legacy/jekyll/` 원본을 유지합니다. 부분 독서 메모이므로 완독일과 새 감상을 임의로 추가하지 않습니다.

## 로컬에서 작성

### 1 새 글 만들기

```sh
npm run new -- --title "손 지지가 끊기는 Climb 전환" --slug climb-hand-contact --topic gameplay --kind devlog --project dcb --series dcb
```

주소는 영문 소문자·숫자·하이픈으로 정하고 공개 후 유지합니다. 같은 주소가 있으면 덮어쓰지 않습니다. `kind`는 `case-study` 구조 노트, `devlog` 개발 기록, `note` 기술 노트, `reading` 읽기 노트입니다.

### 2 메타데이터 채우기

```yaml
---
title: "손 지지가 끊기는 Climb 전환"
description: "같은 지형과 입력에서 접촉 해제 시점을 비교한 기록입니다."
slug: "climb-hand-contact"
date: "2026-10-17"
topic: "gameplay"
kind: "devlog"
tags: ["Unity", "IK", "Traversal"]
project: "dcb"
series: "dcb"
order: 7
draft: true
---
```

날짜는 한국 기준 `YYYY-MM-DD`입니다. 글 생성 명령이 오늘 날짜를 채웁니다. 큰 수정에는 `updated`를 추가합니다. DCB 시리즈 글은 `order` 순으로 연결되고, 태그는 기존 표기를 재사용합니다.

Home의 Pinned 목록은 수정 모드에서 관리합니다. 저장 버튼은 선택한 slug 순서를 담은 `content/pins/<시각>-<식별자>.json` 새 파일 작성 화면을 엽니다. 기존 글 본문을 재작성하지 않고 전체 고정 목록을 한 번의 GitHub 커밋으로 저장하기 위한 방식입니다. 브라우저에서 API 토큰을 받거나 저장하지 않습니다.

빌드는 유효한 설정 중 `createdAt`이 가장 최근인 목록을 사용합니다. 빈 `pins: []`도 전체 해제 설정으로 반영합니다. 삭제되거나 초안인 글은 표시하지 않고 나머지 글의 순서를 유지합니다. 설정을 되돌릴 때는 수정 모드에서 원하는 순서로 다시 저장하거나 해당 변경을 Git에서 되돌립니다. JSON 설정이 아직 없을 때만 글의 기존 `pinned: true`·`pinOrder` 메타데이터를 사용합니다. JSON이 생긴 뒤에는 글 메타데이터만 바꾸어도 고정 설정이 바뀌지 않습니다.

기존 기록을 옮기는 글은 출처 날짜를 사용합니다. 노션 기반 글은 중심 원문의 **생성일**을 `date`에 쓰고 `dateBasis: "notion"`을 지정합니다. 마지막 수정일을 생성일 대신 쓰지 않습니다. 작업 이력 기반 글은 본문에서 다룬 대표 커밋의 작성 시각(AuthorDate)을 한국 날짜로 바꾸고 `dateBasis: "commit"`을 씁니다. 체리픽·병합 후의 반영일(CommitDate)과 구분합니다. 참고 자료가 여러 개면 중심 원문과 보조 자료를 구분합니다.

새로 작성한 학습 글·블로그 목차는 실제 블로그 작성일을 사용합니다(`dateBasis` 기본값은 `authored`). Jekyll 원본 두 글은 기존 작성일과 주소를 유지합니다(`legacy`). 원문 날짜로 바꾸거나 본문을 보완하면 `updated`에 해당 수정일을 기록합니다. 화면에는 노션 원문·작업 기록 날짜와 수정일을 구분해 표시합니다. 2026년 10월 전체 조사 결과와 글별 근거는 [날짜 조사 기록](ARTICLE-DATES.md), [날짜 근거 데이터](ARTICLE-DATES.json)에 있습니다.

### 3 본문 구성

대표 사례는 **문제 → 구조와 구현 → 선택과 비용 → 검증 범위 → 남은 일**로 작성합니다. 개발 기록은 목표·관찰·결과·다음 작업으로 짧게 남겨도 됩니다. 제목은 위 메타데이터가 표시하므로 본문은 `##`부터 시작합니다. `##`, `###`는 우측 목차에 자동으로 나타납니다.

코드 블록에 `csharp`, `hlsl`, `json` 등의 언어를 적으면 강조와 복사 버튼이 붙습니다. 흐름도는 `mermaid` 코드 블록으로, 수식은 `$...$` 또는 `$$...$$`로 작성합니다. 표는 일반 Markdown 표를 사용합니다.

이미지는 `public/media/글주소/`에 넣고 `/media/글주소/이미지.webp`처럼 참조합니다. 큰 영상은 사용자 소유의 공개 영상 링크를 사용합니다. 실제 장면이 준비되지 않았으면 영상 버튼이나 가짜 썸네일을 만들지 않습니다.

실제 플레이 영상은 [촬영·첨부 계획](DCB-CAPTURE-PLAN.md)을 따릅니다. 사용자 선택에 따라 YouTube 등에 업로드한 뒤 본문에 삽입합니다. 원본은 Git에서 제외한 `media-inbox/`에 보관하고, 별도로 쓸 실제 대표 이미지만 `public/media/<slug>/`에 넣습니다. [촬영 기록](templates/DCB-TAKE.md)에 커밋·실행 환경·타임코드·확인 범위를 남기고 [YouTube 양식](templates/youtube-figure.html)을 실제 영상 ID와 설명으로 채웁니다. `.article-video`는 16:9 비율과 최소 높이 200px로 영상·캡션을 표시하며, 자동 재생 없이 지연 로드·모바일 인라인 재생·전체 화면과 원본 링크를 제공합니다. 실제 YouTube 영상이 준비되기 전에는 양식을 공개 글에 붙이지 않습니다.

### 4 로컬에서 보기

`npm run dev`의 주소를 엽니다. 이때 초안에는 로컬 표시가 붙습니다. 공개 상태를 확인하려면 `npm run verify` 후 `npm run preview`를 사용합니다. 초안은 정적 페이지·목록·본문 검색·RSS·sitemap에 포함되지 않습니다.

제목과 본문, 태그는 글 모아보기에서 함께 검색합니다. 검색어와 필터는 URL에 반영되어 같은 결과를 링크로 공유할 수 있습니다. 검색창 단축키는 `/`입니다.

### 5 공개하기

설명과 본문을 완성한 뒤 `draft: false`로 바꿉니다. `npm run verify`를 통과하고 커밋한 뒤 `main`에 push합니다. Actions의 배포가 성공하면 같은 주소에 반영됩니다.

DCB 소개의 **구현한 기능**은 `src/data/dcb-features.mjs`에서 관리합니다. 기능의 `title`·`description`은 글 제목과 별도입니다. `overviewSlug`에 현재 기능 설명 한 편을 지정하고, `articleSlugs`에는 그 아래에 표시할 구현·분석 글을 읽는 순서대로 넣습니다. 기능을 누르면 `/portfolio/dcb/features/<기능 slug>/`에서 **기능 설명 → 구현·분석 글** 두 영역으로 보여 줍니다. 중복 지정한 설명 글은 분석 목록에 다시 표시하지 않습니다. 공개 빌드는 초안·삭제된 글을 제외하고 로컬 dev에서만 초안 배지를 붙여 표시합니다. 기능의 전체 글 수와 sitemap도 같은 설정을 사용합니다. 설명이 없거나 초안이어도 분석 목록과 기능 제목은 유지하며 기존 글 주소는 바꾸지 않습니다. 기능별 순서는 시리즈의 `order`와 별개입니다.

현재 여러 경로의 동작을 종합해 새로 작성한 기능 안내는 블로그 작성일과 `dateBasis: authored`를 사용하고 본문에 소스·설정 확인일을 적습니다. 기존 작업 분석을 분리한 글은 설명하는 원래 작업의 대표 커밋 날짜를 유지합니다. 첫 글은 현재 사용 흐름·화면·규칙을 먼저 설명하고, 구체적인 수정과 측정 근거는 분석 글로 연결합니다.

이동 속도·스태미너·회복·행동/입력 제어의 분석은 기능 `gameplay-balancing`과 태그 `Balancing`으로 묶습니다. 분류는 기존 `gameplay`, 시리즈는 `dcb`를 유지합니다. [밸런싱 글 구성](DCB-BALANCING-PLAN.md)의 순서와 [작성 양식](templates/DCB-BALANCE-CASE.md)을 참고해 초안으로 시작하고, 공개된 분석을 해당 기능의 `articleSlugs`에 추가합니다. 짐·다리의 물리 표현과 이동 규칙의 관련 링크는 유지하되 기능별 분석 목록에서 구분합니다.

밸런스 값을 편집·관찰하는 에디터 도구 제작 경험은 `tools`에 두고, 같은 `Balancing` 태그와 DCB 기능 목록으로 연결합니다. 도구의 계산 표, 런타임 표시 기능과 이번 실행 검증은 구분해 설명합니다.

공개 전에는 원본 자산과 본인 기여, AI 보조 범위, 실제 측정 조건을 확인합니다. private 게임 저장소의 전체 코드·로컬 경로·로그·세이브는 블로그에 복사하지 않습니다.
