# DCB 전체 소개·기능별 영상 스토리보드

작성일: **2026-10-21**. 새 촬영·편집의 상태는 `planned`다. 아래 시각은 편집본의 목표 구간이며 실제 원본 타임코드가 아니다.

## 1. 전체 영상의 중심

**지게를 멘 인물이 산길을 지나고, 지형과 적에 대응한 뒤 신사에서 기도하고 다시 걷는다.**

제목 후보는 **「DCB — 지게를 메고 산길을 지나는 플레이」**다. 한 번의 여정처럼 행동의 앞뒤가 이어지는 약 **110초**의 게임플레이 소개로 만든다. 처음부터 지게와 실제 조작을 보여 주고, 전투가 끝난 뒤에도 이동이 계속되는 것으로 마무리한다. 서로 떨어진 촬영 구간은 공간 전환 컷으로 구분하며, 실제로 이어지는 단일 경로나 배달 임무를 촬영했다고 설명하지 않는다.

장비 조합은 별도 상세 영상에서 선택·완성·장착을 충분히 보여 준다. 물과 불의 상세 표현도 각각의 영상에서 다루고, 전체본에서는 이동 경로의 배경으로 사용한다. 전체본과 상세본은 같은 원본에서 골라 쓰되 역할과 길이를 나눈다.

| 산출물 | 보는 사람이 알아야 할 내용 | 편집 방식 |
| --- | --- | --- |
| 전체 소개 `MAIN` | 지게를 메고 어떤 장소를 지나며 어떻게 행동하는 게임인가 | 일반 게임 시점 중심. 행동과 결과, 공간 전환을 연결 |
| 기능별 `V01`~`V05` | 해당 기능을 어떻게 조작하고 어떤 결과를 얻는가 | 기능마다 시작 조건 → 조작 → 결과 → 복귀를 단독으로 이해 |
| 추가 편집본 `V06`~`V09` | 짐·다리·조합 연출·기도에서 특히 볼 부분 | 본편과 장비 영상에 필요한 원본에서 추출. 독립 편집본 제작은 여유에 따라 진행 |

### 기존 90초 초안에서 바꾸는 부분

- 장면마다 새 기능을 소개하던 흐름을 이동 → 장애물 → 위협 → 대응 → 이동 재개로 연결한다.
- 전투는 사용자가 직접 촬영한다. 공격 예고와 대응이 읽히는 교환을 원본에서 확보한다.
- 타격 직후와 트레버설 도중에 자르지 않고, 일반 자세·보행으로 돌아오는 구간을 남긴다.
- 장비 UI의 조합 결과와 지게 막대 전투를 같은 무기의 사용 결과로 연결하지 않는다. 새 장비 영상에서는 실제로 장착한 동일 조합을 확인한다.
- 10월 20일 대표본 90초·신사 미리보기 26초는 로컬 촬영 초안으로 보존한다. 새 완성본으로 자동 채택하지 않으며, 필요한 구간은 테이크 단위로 다시 검토한다.

첫 21초는 출발과 한 번의 지형 통과에 사용하고 곧바로 적을 보여 준다. 짐·다리·트레버설을 모두 소개한 뒤 전투를 시작하는 순서를 피한다. 위 초수는 목표 배분이다. 트레버설·기도의 실제 지속 시간이 더 길면 완결된 동작을 남기고 도입·연결 컷을 줄이며, 그래도 부족하면 본편 길이를 늘린다.

### 소리·문구·연결

- 발걸음·나무 막대·무기·물·기도 소리를 먼저 확보한다. 음악은 장면 전환과 템포를 보조하며 적의 예고·회피·명중음을 덮지 않는다.
- 첫 게임 소리는 첫 화면부터 들리게 한다. 긴 로고·검은 화면으로 시작하지 않는다.
- 전체본의 기본 자막은 제목과 마지막 표기다. 설명이 꼭 필요한 경우만 한 줄 추가한다. C# 상태명·성능 수치·내부 도구 설명은 상세 영상과 본문에서 다룬다.
- 전투 HUD는 체력·스태미나 등 판단에 필요한 부분을 유지한다. 장비 편집 화면에서는 겹친 월드 HUD와 툴팁이 조립 과정을 가리지 않는 테이크를 고른다.
- 걸어 나가는 방향과 다음 컷의 진입 방향을 맞춘다. 공간이 바뀌면 짧은 전경을 두어 위치 변화를 알 수 있게 한다.
- 촬영 설정·편집 여부와 담당 범위, AI 사용·기존 모델/애니메이션 활용은 영상 설명과 블로그 캡션에 기록한다. 현재 소개 문구의 기여 범위를 따른다.

캐시 반복을 두 번 이상 지나는 긴 원본도 확보하고, 반복 경계를 확인한 경우에만 그 구간을 본문 해당 절에 사용한다. 일반 재생 영상에 FPS 개선율이나 GPU 성능 자막을 넣지 않는다. 화면 밖 생략·복귀와 성능 측정은 CAP-07·12의 별도 조건을 따른다.

### 도구·분석 글은 필요한 근거를 별도로 준비

FSM 글은 실제 사용한 작은 정의·상태 뷰어와 같은 패턴의 전투를 연결할 때 15~25초를 추가한다. 일반 스폰과 선택 개체 시험 적용을 구분한다. 오늘 기본 여섯 편을 마무리한 뒤 확보한다.

AI 활용 글은 실제 요구·후보·본인 선택·검증·통합을 설명하는 도식과 기록으로 보충한다. 밸런싱은 같은 경로·자원·장비·입력의 비교가 있을 때, 시네마틱은 구역 진입 전후 월드·조작 재개를 연속 촬영했을 때 각각의 글에 연결한다. 분위기 컷으로 해당 검증을 대신하지 않는다.

영상 속 순서와 실제 작업 순서를 나눈다. 사용자가 직접 찍는 전투와 핵심 구현 세 편의 원본을 먼저 확보하고, 전체본은 검토한 짧은 영상의 원본에서 편집한다.

| 순서 | 작업 | 그 단계에서 남길 결과 |

## 6. 촬영·편집 공통 기준

- 기본 녹화 후보는 1920×1080의 안정적인 60fps다. 장비가 유지하지 못하면 30fps로 통일하고 실제 값을 기록한다. 정상 속도 원본을 우선하며 녹화 fps를 게임 성능 수치로 사용하지 않는다.
- 실제 플레이 시점으로 기능을 보여 준다. 근접 촬영은 같은 행동의 보충 테이크로 남긴다. Steam도 플레이 시점의 게임플레이와 필요한 HUD 활용을 권장한다. [Steamworks 영상 안내](https://partner.steamgames.com/doc/store/trailer)
- 조작 시작 전 2~3초, 행동 종료 후 3~5초를 더 녹화한다. 특히 공격·트레버설·기도의 복귀를 남긴다.
- 원본은 게임 소리를 먼저 담고, 음악은 편집에서 조절한다. OBS는 녹음 트랙을 나눌 수 있고 MKV 녹화 후 MP4로 remux할 수 있다. [OBS 녹화 안내](https://obsproject.com/kb/standard-recording-output-guide)
- 전투 한 교환과 트레버설 한 동작은 읽히는 단위로 유지한다. 행동 원인이 보이기 전에 타격·빛의 절정으로 건너뛰지 않는다.
- 60fps 정상 속도 소스를 30fps 편집본으로 내보내더라도 정상 재생 시간을 유지한다. 슬로모션은 해당 구간에 배속을 표시하고 원본을 보관한다.
- 동일 조합·무기·지게 상태와 이동 방향을 컷 사이에서 확인한다. 카메라나 공간이 바뀌면 전경으로 새 위치를 알린다.

## 7. 마무리와 블로그 연결

### 파일 정리

원본·편집본은 Git에서 제외한 `media-inbox/` 아래에 둔다. 아래 이름은 예정 이름이며 현재 파일이 있다는 뜻이 아니다. 실제 촬영일이 달라지면 날짜를 바꾼다.

```text
2026-10-21_V01_combat_take01_raw.mp4
2026-10-21_V01_combat_cut_v01.mp4
2026-10-21_MAIN_gameplay_cut_v01.mp4
```

take마다 [촬영 기록 양식](templates/DCB-TAKE.md)에 실제 원본 위치·사용 구간·실행 모드·변경 상태·해상도·녹화 fps·확인 범위를 적는다. 공개 캡션은 다음 틀을 실제 값으로 채운다.

> [기능과 실제 동작]. [촬영일], [Editor Game View 또는 Player], [해상도·녹화 fps], 정상 속도. [편집·생략한 구간과 확인한 범위].

### 편집본 완료 기준

- [ ] MAIN은 출발 → 통과 → 대응 → 이동 재개 → 기도 후 복귀로 이해된다.
- [ ] V01~V05는 각각 단독 재생해도 시작 조건·행동·결과가 읽힌다.
- [ ] 전투·트레버설·기도의 마지막 자세와 입력/보행 복귀를 확인했다.
- [ ] 조합 화면과 실제 장착 무기의 파츠가 일치한다.
- [ ] 정상 속도·음성/효과음·가림·프레임 끊김을 실제 파일로 재생해 확인했다.
- [ ] 원본과 편집본을 구분했고 사용할 구간·대표 프레임을 기록했다.
- [ ] 아직 촬영하지 못한 항목을 남겼고 전체 기능 검증으로 확대하지 않았다.

오늘의 **편집 마무리**는 위 기준을 만족하는 파일과 구간표 확보까지다. 블로그의 **첨부 마무리**는 실제 영상 URL을 등록하고 데스크톱·모바일에서 공개 재생을 확인한 단계까지다. 두 상태를 섞지 않는다.

### 현재 사이트에 연결하는 방법

1. 검토한 편집본을 사용자 채널에 올리고 실제 공개 범위와 삽입 허용 여부를 정한다.
2. 지원용 포트폴리오의 Edit → DCB 영상·GIF에서 MAIN은 `project`, V01~V05는 각 슬롯에 등록한다.
3. 글 본문에는 해당 설명 옆에 [YouTube 양식](templates/youtube-figure.html)을 실제 주소·구간·캡션으로 채워 넣는다. 본문에 전체 소개본을 매번 반복하지 않고 해당 기능의 상세본을 우선한다.
4. V06~V09는 글의 본문 구간으로 연결한다. 신사 두 초안의 공개 여부는 별도로 정한다.
5. `planned → recorded → reviewed → approved → attached → live-checked`의 실제 진행 상태를 기록한다. 사이트 반영 시 `npm run verify`와 데스크톱·모바일 재생을 확인한다.

이번 문서는 컨셉·촬영·편집 계획이다. 새 게임 실행·촬영·편집 파일 생성·업로드·본문 영상 등록·공개는 수행하지 않았다.
