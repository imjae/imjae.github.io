## AI 사용 범위

DCB 개발에서 코드 초안, 구현 대안과 검증 도구를 작성할 때 AI를 사용했다. 요구사항과 제약을 정하고, 나온 결과를 수정·검증하는 작업은 직접 진행했다.

## 작업 조건 지정

트레버설은 Avatar, 지형, 입력과 문제가 발생하는 구간을 정한다. 이펙트는 카메라, 재생 시점과 주변 환경을 정한다. 조건을 고정한 뒤 구현 후보를 비교한다.

수정 전에는 실제 씬에서 사용하는 스크립트, 프리팹, 재질, 클립과 데이터를 확인한다. 코드에서 가정한 프리팹이나 데이터와 씬에 연결된 것이 다르면 에디터 도구와 게임 실행 결과가 달라질 수 있다.

## 검증 항목

| 확인 항목 | 확인하는 내용 |
| --- | --- |
| 컴파일·임포트 | 코드가 컴파일되고 자산을 임포트할 수 있는지 |
| 자동 검사 | 계산·상태·데이터 규칙을 지키는지 |
| 실제 재생 | 상태 전환, 재생·정지와 풀 반환이 정상적으로 처리되는지 |
| 화면·성능 비교 | 움직임·표현과 실행 비용이 어떤지 |

IK는 자동 검사를 통과해도 손목이 비틀리거나 보행 전환에서 발이 튈 수 있다. 이펙트는 프리뷰에서 보여도 실제 게임 카메라나 배포 빌드에서는 결과가 달라질 수 있다. 자동 검사와 실제 실행을 따로 확인한다.

## 작업 기록

작업마다 재현 조건, 수정한 내용, 비교 결과와 남은 문제를 적는다. 채택하지 않은 구현도 이유를 남긴다. 재사용 자산, AI 보조와 직접 담당한 범위는 구분해서 설명한다.

기능별 구현과 검증 결과는 DCB 시리즈의 각 글에 정리했다.
